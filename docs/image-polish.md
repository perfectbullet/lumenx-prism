# 图像描述润色

图像制作台的“润色”读取当前外貌/场景/道具描述、画风、补充要求及全部角色细节，以异步文本任务执行。完成后展示润色前后对比和冲突/待确认内容；用户确认“应用到表单”后才更新描述和建议中的角色字段，不自动生成图片。建议描述也可继续编辑。

## 角色信息优先级

不可改变的身份特征优先；当前非空年龄、体型、发型和服装覆盖旧描述或参考图中冲突的同类信息；画风只影响渲染表现。图片提示词升级为 `asset-production-v6`，用自然语言明确当前细节优先级并重复最终要求，原请求仍原样冻结。历史任务不重写。模型遵从仍需看图确认，不能以提示词或单个结果保证年龄、身份绝对准确。

例如旧描述是32岁、深灰卫衣，当前细节是23岁、浅灰衬衣，润色后的描述采用23岁和浅灰衬衣，并说明冲突来源。习惯不直接转换为可见特征：“不喜欢刮胡子”不会自动变成络腮胡，“喜欢喝咖啡”不会自动增加手持咖啡杯。要显示这些内容应明确写出胡茬或具体道具。

润色保留明确填写的角色字段、姓名、作用、身份特征和表情，移除误填在道具中的习惯；不新增原道具列表之外的物品。润色不读取图片内容，不改变已选参考图、生成参数或风格选择。若等待期间表单变化，禁止直接应用过期建议，需要基于当前输入重新润色。

## 模型与接口

模型配置仅从 MongoDB `model_comfigs` 读取，新增用途绑定 `image_polish_id`；模型页点击“用于图像描述润色”。可与实体提取使用同一个已配置文本模型，但绑定独立，无环境变量回退。

- `PUT /v1/model-configs/{id}/image-polish`：绑定已启用文本 Chat Completions 配置。
- `POST /v1/images/polish/jobs`：提交 `asset_type/name/description/style/prompt/character_card`，需 `Idempotency-Key`，返回202、任务ID与Location。
- `GET /v1/jobs/{id}`：查询排队、处理、成功或失败；任务类型为 `image_polish`，也可通过任务列表按type筛选。

输入、实际提示词、无密钥模型快照、原始模型输出和建议保存在 `ai_jobs`。结果字段为 `suggestion`（description、character_card、warnings）与 `review_required`。接口校验拒绝改写明确指定的角色字段、身份特征及新增道具；自然语言建议仍需用户确认。

由 text-worker 执行，不占用图片/视频的GPU资源槽。页面重新打开可查询未完成润色，输入不同则阻止应用。提交未确认时相同输入复用标识。模型调用中断不自动重发；收到的输出已保存时重启可继续解析和落库，不重复调用模型。
