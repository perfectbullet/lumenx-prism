# 作品库与分集确认（第一阶段）

导航顺序：作品库 → 剧本制作规划 → 实体提取 → 图像制作台 → 分镜制作台 → 视频制作台。

`/tools/works` 支持 UTF-8 TXT/Markdown（400KB、8万字以内）和粘贴文本，名称必填，类型为小说/剧本/故事。原文保存后不覆盖；改稿可另建作品。作品显示名称可以改，UUID 不变。AI 分集建议同时提供项目简报、故事大纲、跨集约定和画风/名称建议，点击后才采用名称。它不会自动扩写小说为完成的拍摄剧本；改编说明、分集与估时都需确认。

MongoDB 使用 `prism_works` 保存原文及哈希，`prism_work_editions` 保存不可变的确认分集版本。分集必须按顺序、无重叠、无遗漏覆盖全部原文行；单集最多3万字。章节并不强制等于集，片尾预告不能扩成新集。用户可改标题、摘要、时长及原文范围，确认时再校验覆盖。重复确认相同来源/内容返回同一个版本，修改后创建新版本，旧任务不变。

新增异步任务 `work_breakdown` 由文本 worker 消费，使用 MongoDB 已绑定的分镜规划模型；推理中断不自动重发，已有原始输出可继续解析。GPU 暂停不阻塞文本任务。

确认后进入 `/tools/scripts` 或 `/tools/entities`。规划页按作品、分集版本和单集分析；实体页支持多集或全部集联合提取，并参考作品已有身份与外观目录。跨集关联需人工确认，不按名字直接合并；重复提交使用幂等标识。规划页已移除测试样本入口，分析记录与已确认制作版本分别展示。

新任务的 `work_context` 冻结 work_id、edition_id、episode_id；后端验证原文与确认版本完全一致。旧任务无关联时照常访问，不猜测归属、不改写原历史。单集规划继承全作品上下文及确认画风、预算，模型不允许将已确认的一集再次拆成多集。场次分镜快照继续保存该来源关联。

## HTTP

- GET/POST `/v1/works`，GET/PATCH `/v1/works/{id}`（PATCH 仅改名，要求 revision）。
- GET/POST `/v1/works/{id}/breakdown/jobs`（POST 要求 Idempotency-Key）。
- GET/POST `/v1/works/{id}/editions`（POST 确认成功分析的可编辑草稿）。
- GET `/v1/works/{id}/editions/{edition_id}`。
- GET `/v1/works/{id}/editions/{edition_id}/episodes/{episode_id}`。
- 实体/规划任务添加可选 work_context；旧接口保持兼容。任务和规划列表支持 work_id、edition_id、episode_id 过滤。

## 作品级实体与批量图片

跨集身份/外观确认、只补缺失图片、自动润色、四张候选和第1张暂选、按作品与集筛选已接入。详见 [作品级制作](work-production.md)。旧实体任务不自动迁移，作品级关联从新的联合提取和确认建立。跨场整集调度/合成仍是独立后续能力。

## 视频制作台合成修复

当前分镜版本支持2～36个镜头。保留“合成已选候选”，新增“全部合成”：按镜头顺序自动选该分镜版本每镜头最新成功候选（finished_at、created_at、id 排序），忽略失败/其他版本。提交时冻结所选任务ID，幂等重试不重新挑选；缺失镜头不跳过。自动选择不覆盖用户的手动选择。

合成结果校验允许最长720秒、最大1GiB，单个模型视频仍限制180秒、256MiB。先检查磁盘空间，逐片转为24fps、AAC立体声再合并，保留音轨。不是跨场整集合成，也不会产生新的推理任务。
