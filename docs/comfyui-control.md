# ComfyUI 管理与任务暂停

页面 `/tools/comfyui` 位于 Prism，管理连接读取现有 MongoDB `model_comfigs` 的 ComfyUI 图片/视频配置，以 base_url 去重。沿用独立 ComfyUI Manager 的“检查队列再请求 /free”原则，通过HTTP操作，不导入同级项目，不提供任意Shell、队列清空或推理中断接口。

## 显卡交接

1. “暂停 GPU 队列”：MongoDB `ai_runtime_controls` 的gpu记录持久化paused；worker不领取新的图片/视频任务，在途任务继续完成。文本任务与CPU视频拼接不受该开关影响。新提交仍可排队。
2. 等待运行任务、资源锁、ComfyUI运行/等待队列都清空，再“释放全部空闲缓存”或释放指定实例。发送unload_models/free_memory，HTTP200仅表示接受请求；页面轮询实际显存。
3. 同事用完后手动“恢复 GPU 队列”。暂停状态跨API/worker重启保留，不因缓存释放自动恢复。

独立GPU worker需保持运行以响应恢复；部署时先写入暂停状态，再启动已更新worker。此控制不停止其他系统或用户直接向ComfyUI提交任务。外部任务不会被清除，队列非空时拒绝释放；外部调度不受Prism资源锁控制，应协调交接。

## 单个任务暂缓

首版入口放在管理页“排队中的图片／视频任务”，原任务页展示“已暂缓”。只允许queued的图片/视频任务原子设置scheduling_paused，领取时排除；HTTP状态仍为queued，保留输入、幂等标识和原排序时间。单任务恢复不解除全局暂停；全局恢复不解除单任务暂缓。running任务不能中途挂起，接口返回409；要让出显卡采用全局暂停并等待。

后续可把同样入口放入图像任务详情和视频镜头候选卡。执行中取消需要单独设计取消、结果未知、资源释放与费用处理，不能把 /interrupt 当作可恢复暂停。

## 保护与接口

领取前检查全局暂停，获取GPU资源前再次检查；释放时原子占用维护标识并获得相同ai_resources资源组锁，拒绝运行任务、未知占用与非空ComfyUI队列。恢复与维护标识在同一个Mongo记录上互斥。未知推理锁不会自动清除。维护进程意外退出若遗留维护标识，应由运维核对任务、上游队列和资源锁后处理，不自动过期后放行。

- GET `/v1/comfyui/status`：调度状态、在途/排队计数、资源占用、实例队列和GPU显存；不返回密钥。
- POST `/v1/gpu/pause`、`/v1/gpu/resume`：全局GPU调度开关。
- POST `/v1/comfyui/free`、`/v1/comfyui/{config_id}/free`：所有或指定实例缓存释放。
- POST `/v1/jobs/{id}/pause`、`/v1/jobs/{id}/resume`：仅排队中的图片/视频任务。

接口沿用Prism当前服务鉴权配置。状态探测失败时不执行强制释放；不会删除权重、缓存文件、历史任务或生成结果。

## 队列来源与筛选

页面名称为 ComfyUI 任务管理。各实例的执行、等待和总数直接读取原生 `/queue`，包括外部直接提交的任务；Prism 排队任务尚未提交时不计入。顶部同时列出 Prism 调度与 ComfyUI 接收数量。队列读取失败显示未知；显存探测失败但队列可读时仍保留实际计数，禁止据此释放缓存。

右侧为 Prism 的排队及执行中图片/视频，支持类型、状态（执行、等待、单独暂缓）和资产/场次/镜头名称搜索，显示可读名称与提交时间，任务编号折叠。刷新保留筛选及滚动位置。暂停/恢复仍只操作 Prism 排队任务，不修改原生 ComfyUI 中的在途任务。

## 实例进程显存

实例卡以 `nvidia-smi --query-compute-apps=pid,used_gpu_memory,gpu_uuid --format=csv,noheader,nounits` 读取进程显存。API 与 ComfyUI 同机时，按 GPU 进程 `/proc/<pid>/cmdline` 中明确的 `main.py --port` 对应实例端口；不依赖固定 PID。独立展示 PID、进程显存、整卡已用/可用、PyTorch 管理显存及空闲缓存。整卡数据为共享指标，不能按实例相加。

接口 `/v1/comfyui/status` 在实例中增加 `process_memory`；单位为字节，采集仅执行固定只读命令，3 秒超时。多 GPU 进程按 GPU 去重后合计。远端实例、权限不足、缺少命令、未知显存和 PID 歧义均显示不可用，不以整卡数据代替进程数据，也不当作 0。页面约每 8 秒自动更新，不修改 GPU 队列或推理进程。

## ComfyUI 任务来源

实例卡列出 `/queue` 中全部正在执行及等待任务，包括其他程序直接提交的任务。按 `prompt_id` 与 `ai_jobs.execution`、图片多次执行和重试历史匹配；提交响应尚未落库时，可核验 `prism_submission_id` 是否属于已保存的执行记录。匹配后标为“Prism 任务”，无记录无标记为“非 Prism 任务”，标记存在但无法核实为“来源待确认”。不展示其他程序的提示词、完整工作流或凭据。缓存释放仍检查所有任务，不能因为它不是 Prism 任务就释放缓存。

## 活动任务与历史任务

右侧默认“活动任务”，只列出等待执行、执行中和单独暂缓的 Prism 图片/视频任务。切换“历史任务”后显示已成功和失败的任务，包含作品图像、提示词生图、镜头视频和独立 H3 视频。每页 20 条，支持类型、结果状态和名称/镜头/任务编号搜索，所有过滤与分页在数据库执行，不仅搜索当前页。

历史接口：`GET /v1/gpu/jobs/history?limit=20&offset=0&type=image_generation&status=succeeded&name_query=名称`。类型、状态和搜索可省略，沿用服务鉴权。返回列表摘要不包含完整请求与结果；点击“查看结果与详情”才读取 `/v1/jobs/{id}` 和媒体文件，支持预览和下载。历史筛选、翻页、刷新和查看详情均为只读操作，不重启任务或改动 GPU 队列。已结束任务不会显示暂缓操作；页面自动刷新保留历史筛选与页码。

列表与结果详情展示 ComfyUI 实际工作流耗时，原始字段为 `execution_timing`。排队任务显示尚未执行；正在运行而没有完整时间记录时显示统计中。历史丢失时显示暂无记录，不使用任务领取至完成的墙钟耗时作为推理耗时。多图任务相加每个唯一 ComfyUI prompt 的执行时间；部分结果明确显示记录数。

显存等待显示为“排队中／显存不足”，附带所需、当前可用及差额。H3 空闲显存门槛至少 30 GiB，队首每 30 秒检查。排队和单独暂缓是不同调度条件：暂缓任务不会自动恢复，全局暂停也不会因显存达标解除。

## 默认图片实例切换（2026-11-03）

默认图片配置绑定至 `http://192.168.100.230:8190`（230 Qwen-Image 2.1，独占 RTX 4080），使用 `resource_group=230-gpu0`、空 `peer_base_urls`。图像制作台和提示词生图的新请求默认使用该实例，图片任务不会为推理请求 231 H3 释放缓存。原 231 图片配置保留供历史记录及显式指定使用；原 H3 配置及其 peer 关系保持原样。切换通过 Prism 自己 MongoDB `model_comfigs` 的默认绑定生效，无需重启服务。

### 迁移后的旧图片 peer

H3 旧任务的模型快照可能仍列有原 231 图片实例作为缓存清理 peer。运行时仅对“已不再是默认图片配置、且无 Prism 排队/执行中图片任务引用”的已登记图片 peer 做兼容：连接明确断开时允许跳过，仍执行 H3 本机队列及至少 30 GiB 空闲显存检查；在线忙碌或响应超时不会被跳过。未登记的 peer 和仍在使用的配置保持必需依赖，暂时不可用时任务排队等待并说明原因。该处理不修改历史任务输入、模型版本或默认视频模型。
